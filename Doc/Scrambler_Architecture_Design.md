## 1. 一句话说清它是什么

**自同步扰码器把数据和一段伪随机序列逐 bit 异或，让线上信号看起来像噪声;接收端用互补电路还原——而且不需要发送端告诉它"密钥",收一小段数据就能自动对上。**

它解决两个问题:

1. **打散数据**:连续发一长串相同的 0 或 1,会让接收端时钟恢复（CDR）失锁、频谱出现尖峰（EMI 超标）。扰码后跳变密度上来了,频谱也摊平了。
2. **自动同步**:解扰端的寄存器里装的不是"自己算出来的密钥",而是**刚收到的线上数据本身**。所以只要数据在流,寄存器自然就被填成和发送端一致——**省掉一整条同步通道,也不用传种子**。

"自同步"三个字的全部价值就在这:**收发两端不靠任何单独的同步信号,仅凭数据流就能对齐。**

## 2. 核心原理（看懂这一节就够了）

### 2.1 扰码与解扰的对称结构

设 `d` = 原始数据,`s` = 扰码后上线的数据,`d̂` = 解扰还原的数据。以两个反馈抽头（tap）在第 `A`、`B` 位为例:

```
发送端(扰码,带反馈) :  s[n]  = d[n] ⊕ s[n−A] ⊕ s[n−B]
接收端(解扰,纯前馈) :  d̂[n] = s[n] ⊕ s[n−A] ⊕ s[n−B]
```

- **发送端**有反馈:输出 `s` 又被移回寄存器参与下一次运算。
- **接收端**是纯前馈:只对收到的 `s` 做异或,没有反馈环。
- 两者互为逆运算——把同一段数据扰码再解扰,原样还原。

### 2.2 为什么不用传种子就能锁定（关键直觉）

把发送端和接收端的寄存器看成**同一条河的同一段水**:

| | 寄存器里装的是 |
|---|---|
| **发送端寄存器** | 我最近**送上线**的那几个 bit |
| **接收端寄存器** | 我最近**从线上收到**的那几个 bit |

无传输错误时,"送出去的 = 收到的"。所以两个寄存器本质上是**同一条数据流最后几个 bit 的两份副本**。接收端只要把收到的 bit 一个个灌进自己的寄存器,**灌满 N 个（N = 寄存器级数）,内容必然和发送端一模一样**——这时解扰公式里的 `s[n−A]`、`s[n−B]` 完美抵销,输出就等于原始数据。

锁定不是靠"对暗号",而是**机械上被逼出来的必然**。

### 2.3 两个免费的好处

- **开机自动锁定**:开机时接收端寄存器是垃圾,但收满 N 个 bit 后必锁。开机只是"寄存器全是垃圾"这个最坏特例而已。
- **自动痊愈（self-healing）**:传输途中被噪声打翻了寄存器里几个 bit?不用慌——之后再收 ≤N 个干净 bit,垃圾被冲光,自动锁回。

### 2.4 一个必须知道的代价:误码倍增

天下没有免费的午餐。乘法型扰码器**会放大错误**:线上一个 bit 错,每次它移位经过一个反馈抽头,就在解扰输出制造一个新错误。**1 个线路 bit 错 → 解扰输出多个 bit 错**(错误个数和多项式抽头数相关)。

> 这意味着:用了自同步扰码器的系统,通常配一套**重传机制**来兜底,而不是单纯靠前向纠错（FEC）——因为错误被放大后,FEC 性价比下降。

### 2.5 一条铁律:种子必须非零

寄存器初值（种子）**必须含至少一个 1**。如果初值全 0,反馈链算出来永远是 0,扰码器等于没干活(输出 = 输入)。这是设计里必须用硬件拦住的死锁状态。

## 3. 架构设计

### 3.1 顶层框图

```
                              scrambler_top
  ┌──────────────────────────────────────────────────────────────────┐
  │                                                                    │
  │   mode ─┐   seed / seed_load ─┐   force_rst ─┐                     │
  │         │                     │              │                     │
  │         ▼                     ▼              ▼                     │
  │   ┌──────────────────────────────────────────────────┐           │
  │   │            Control & Status (CSR)                 │           │
  │   │  - 模式: scramble / descramble / bypass / loopback│           │
  │   │  - 种子加载 + 非零校验(防死锁)                      │           │
  │   │  - 强制复位(测试用,可重复波形)                     │           │
  │   │  - 状态监测: locked / all-zero / parity-err        │           │
  │   └───────────────┬──────────────────┬─────────────────┘           │
  │                   │ seed, force_rst  │ status                      │

  │ din ─▶│   scrambler_core    │   │  descrambler_core   │─▶ dout     │
  │       │   (TX, 带反馈)       │   │   (RX, 纯前馈)       │            │
  │       │   state[N-1:0]      │   │   state[N-1:0]      │            │
  │       └───────────┬─────────┘   └────┬────────────────┘            │
  │                   └─────────┬─────────┘                            │
  │                       ┌─────▼─────┐                                │
  │              din ────▶│  out mux  │──────────────────────▶ dout    │
  │             (bypass)   └───────────┘                               │
  └──────────────────────────────────────────────────────────────────┘
```

三个角色:

- **`scrambler_core`** —— 发送端,带反馈,把数据扰码。
- **`descrambler_core`** —— 接收端,纯前馈,把数据还原。
- **`scrambler_top`** —— 封装两个核,提供配置寄存器、种子加载、Bypass、自测和状态监测。

全双工应用两个核都例化;单工只用其中之一。

### 3.2 并行处理:每时钟搬 W 个 bit（工业实现的关键）

原理上扰码器是逐 bit 串行的,但实际数据通路一拍要处理 W 个 bit（如 8 或 16）。做法是把串行递推**展开成单周期组合逻辑**:维护一个 N-bit 状态寄存器,每拍一次性算出 W 个输出 bit,再把这 W 个 bit 整体移入状态寄存器。

**一个很省事的性质**:只要**最小抽头位置 > W**(例如最小抽头在第 19 位、W=8 或 16),那么同一拍内 W 个输出 bit 所依赖的历史 bit **全部落在本拍窗口之前**——即**窗口内各 bit 互不依赖**。

结果:
- 发送端虽带反馈,但在这个条件下**退化成纯组合、没有窗口内递归**,关键路径只有 **2 级异或**。
- 接收端本就纯前馈,组合深度恒为 **2 级异或**。

⇒ 8-bit / 16-bit 并行版本时序非常宽松,高速下也**无需插流水**。

### 3.3 一个隐蔽的大坑:位序（`BIT_ORDER`）

#### 3.3.1 矛盾从哪来:线是"一根"的,总线是"一排"的

扰码器本质是**串行**的——数据在物理线上是一个 bit 接一个 bit 按时间先后流过去的,时间上有严格的"谁先谁后"。但并行实现一拍要处理 W 个 bit,用的是一根 W 位宽的总线 `din[W-1:0]`,这"一排"线是**同时**到达的,彼此没有时间先后。

于是产生一个**没有天经地义答案**的问题:

> 这一排 W 个 bit,**谁先上线?** —— 这是一个**约定**,不是事实。

常见两种:

| 约定 | 含义 |
|---|---|
| **LSB-first(低位先)** | `din[0]` 时间最先,然后 `din[1]`…最后 `din[W-1]` |
| **MSB-first(高位先)** | `din[W-1]` 时间最先,然后 `din[W-2]`…最后 `din[0]` |

不同协议各有规定,两种都合法。

#### 3.3.2 为什么是"隐蔽"大坑

扰码器的全套数学——抽头取哪一位、移位往哪边挪——**全建立在"时间先后"上**(公式里的 `s[n-A]` 指的是时间上 A 拍之前)。所以核内部必须有一个**唯一的、铁定的**时间约定。**本设计核内统一规定:`index 0 = 时间最先`(`din[0]` 最先上线)**,抽头映射、移位写回都按这个来,并已逐 bit 验证正确。

如果对端用相反约定(高位先),而核认死了低位先,核就会把整个字的时间顺序**整体读反**。每一步 LFSR 数学都"正确"地算,但喂进去的时间顺序是错的 → **解出来全是垃圾**;又因为每步看起来都对,debug 时根本找不到错在哪。

#### 3.3.3 全展开例子(W=4,外部用 MSB-first)

想发的线上时间流是 `1 → 0 → 1 → 1`(第 1 个最早)。外部 MSB-first 约定下,它被摆成 `din = 1011`(`din[3]`=最早):

| 总线位置 | din[3] | din[2] | din[1] | din[0] |
|---|---|---|---|---|
| 时间序 | 第1(最早) | 第2 | 第3 | 第4(最晚) |
| 值 | 1 | 0 | 1 | 1 |

**若直接喂给核**(核认"index 0 最早"):核以为时间流是 `din[0]→din[3]` = `1 → 1 → 0 → 1`,**和真相 `1 → 0 → 1 → 1` 相反** → 垃圾。

**进门翻转** `din_core[i] = din[W-1-i]`:得到 `din_core` = 时间序 `1,0,1,1`,核理解正确 ✓。

核算完吐出的 `scrambler_out` 也是时间序(`[0]`=最早)。**出门若不翻**,直接 `dout = scrambler_out`,则 `dout[0]` 成了最早;但外部 MSB-first 坚持认为 `dout[3]` 才是最早 → 对端又把输出读反 → 还是垃圾。所以**出门也要翻** `dout[i] = scrambler_out[W-1-i]`,让最早的 bit 回到 `dout[3]`。

#### 3.3.4 `BIT_ORDER` 的解法:只在大门两侧翻译,内部数学不动

核像一个只懂一种语言的工人。`BIT_ORDER` 是守在进出口的**翻译官**:

```
外部世界 ──(进门翻转)──▶ 核(只认 index0=最早)──(出门翻转)──▶ 外部世界
```

- `BIT_ORDER = 0`:外部本就 LSB-first,进出口**都直通**。
- `BIT_ORDER = 1`:外部 MSB-first,进出口**都做镜像翻转** `[i] = [W-1-i]`。

**两条铁律**:
1. **进、出口都要翻**——只翻一头,等于工人听懂了客人、回答客人却听不懂,照样对不上。
2. **两处翻转规则必须完全一致**——否则一进一出规则不一,自己跟自己都对不上。

这样做的好处:位序的全部影响被隔离成进出口两个"翻不翻"的开关,**核内部永远只有一种已验证正确的形态**,绝不去改风险最高的抽头/移位逻辑。验证阶段再用已知向量对两种 `BIT_ORDER` 逐 bit 比对锁死。

## 5. 实现方法

> 本节只描述数据通路行为与策略,不含代码。

### 5.1 全部参数化

| 参数 | 含义 | 默认 |
|---|---|---|
| `N` | LFSR 级数(寄存器长度) | **58** |
| `W` | 每时钟数据位宽 | 8 |
| `TAP_A` / `TAP_B` | 两个反馈抽头位置 | 可配置 |
| `BIT_ORDER` | 位序对齐开关 | 0 |

把级数和抽头做成参数,好处:① 同一份 RTL 适配不同多项式和宽度;② 验证时可退化成小级数(如 N=3)做**手算回归**。

### 5.2 发送端核（带反馈）

1. 维护一个 N-bit 状态寄存器,存"最近送上线的 N 个输出 bit"。
2. 每拍取 W 个数据 bit,按 `s = d ⊕ state[A] ⊕ state[B]` **并行**算出 W 个输出 bit。
3. 把这 W 个**新产生的输出 bit** 移入状态寄存器。
4. 输出 W-bit 扰码结果。

#### 5.2.1 移位写回的位映射（与 `BIT_ORDER` 无关）

核内约定 **`state[k] = s[n-1-k]`,index 越小 = 时间越新**(`state[0]` 是最近一次输出)。本拍产生的 W 个输出在时间上是 `scrambler_out[0]` 最早 → `scrambler_out[W-1]` 最晚。写回规则:

```
state[j]  <= scrambler_out[W-1-j]   // j = 0..W-1 (本拍新输出,倒序填入低端)
state[k]  <= state[k-W]             // k = W..N-1 (旧状态整体上移 W 位)
```

以 W=8 为例,逐 flop 展开:

| 来源 | scrambler_out[0] | scrambler_out[1] | … | scrambler_out[6] | scrambler_out[7] |
|---|---|---|---|---|---|
| 去向 | `state[7]` | `state[6]` | … | `state[1]` | `state[0]` |
| 时间 | 最早 | … | | | 最晚 |

**为什么这样填**:`state[0]` 必须装"最新"的输出,而最新 = 时间最晚 = `scrambler_out[W-1]`;`scrambler_out[0]` 是这批里**最旧**的,自然落到这批的**最高 index** `state[W-1]`。所以"`scrambler_out[0]` 跑到了 MSB 位置"这个观察是对的——但精确地说,它是**本拍刚移入的 W 个 flop 里的最高位 `state[W-1]`**,而非整个 N-bit 寄存器的 MSB `state[N-1]`。

**与 `BIT_ORDER` 无关**:`scrambler_out` 与 `state` 都活在核内部"index 0 = 时间最先"的约定里;`BIT_ORDER` 只在 `din` 进门、`dout` 出门两处翻转(见 3.3),**碰不到**这条内部移位通路。因此无论 `BIT_ORDER=0` 还是 `1`,映射 `scrambler_out[0] → state[W-1]` 恒定不变。

### 5.3 接收端核（纯前馈）

1. 维护 N-bit 状态寄存器,存"最近收到的 N 个输入 bit"。
2. 每拍取 W 个收到的 bit,按 `d̂ = s ⊕ state[A] ⊕ state[B]` **并行**算出 W 个输出 bit(组合)。
3. 把这 W 个**收到的输入 bit**(不是输出 bit)移入状态寄存器。
4. 一个填充计数器累计有效**周期**,达到 `LOCK_CYCLES = ceil(N/W)` 后拉高 `locked`(粘滞,复位 / `force_rst` 前保持)。因为一拍进 W 个 bit,收满 N 个 bit 只需 `ceil(N/W)` 个有效周期,而非 N 个。
5. **输出寄存 + `locked` 门控**:把第 2 步的组合结果与其 valid **一起打一拍寄存器**输出,并用 `locked` 门控——锁定前 `dout_valid=0`、`dout=0`(挡住同步期间的垃圾),锁定后逐拍放出还原数据。代价是输出 +1 拍延迟;好处是给下游一个"一拍一个、valid 只在同步后为 1"的干净接口。

> ✅ 发送端和接收端的唯一区别:**发送端移入"自己的输出"(所以有反馈),接收端移入"收到的输入"(所以纯前馈)。** 记住这一句,两个核就全懂了。
>
> ✅ `locked` 的拉高时刻与寄存器真正灌满**精确对齐**(v1.3 修正):在第 `ceil(N/W)` 个有效拍末拉高,被压掉的正是同步期间那 `ceil(N/W)` 个本来就不可信的字,**从第一个可正确还原的字起一个不丢**。输出仍有 +1 拍寄存延迟,需计入链路预算。

### 5.4 种子加载与防死锁

- 软件写好种子寄存器,再写 `LOAD` 触发加载。
- 加载前先判断种子是否非零:非零才放行并置 `NONZERO_OK`;**全零则拒绝加载并告警**,从硬件上堵死 LFSR 死锁。
- 运行中持续监测状态是否变成全零,作为活性检查。

### 5.5 测试模式（可重复波形）

- 开启后,内部计数器每数到 `PERIOD` 就把状态强制置全 1。这会把超长的伪随机序列截短成**可重复的固定波形**,方便用示波器抓取和合规测试。
- 正常工作时关闭,走纯自同步,不传种子、不强制复位。

### 5.6 Bypass / Loopback

- **Bypass**:`dout = din`,状态冻结,用于绕开扰码做裸数据透传或调试。
- **Loopback**:发送端核输出直连接收端核输入,做片内自测——验证"扰码再解扰 = 原数据"。

### 5.9 RTL 实现要点（知识点固化，v1.1）

> 以下是 RTL 落地时踩过/确认过的关键决策,固化成文,避免后人重蹈。

**(1) 位序 `BIT_ORDER`——隐蔽大坑的根治法**
核内部所有数学锁定一个唯一约定:**`index 0 = 时间最先`**。外部总线若用相反约定(MSB-first),不能去改内部抽头/移位逻辑(改那里最易引入新 bug),而是在**进出口各做一次镜像翻转** `[i]=[W-1-i]`,且两处规则必须**完全一致**。只翻一头 → 一进一出对不上 → 解出垃圾且极难查。`BIT_ORDER=0` 时两端直通,`=1` 时两端镜像。

**(2) 参数合法性——`initial` + `$fatal` 守门**
输出写法 `state[TAP_A-i-1]`、`state[TAP_B-i-1]`(`i` 取 0..W-1)隐含三条约束,非法例化必须在 elaboration 阶段就炸出来,而不是默默生成越界/负索引逻辑:

| 约束 | 原因 |
|---|---|
| `TAP_A > W` | 否则 `i=W-1` 时索引 ≤ 0 → 窗口内递归或负索引;且 `> W` 保证窗口内无递归(关键路径恒 2 级异或) |
| `TAP_B ≤ N` | 最大索引 `TAP_B-1` 必须 ≤ `N-1`;**等号合法**(默认 58=58,正好用满 `state[57]`) |
| `TAP_A < TAP_B` | 约定 A 为较小抽头、B 为较大抽头,保证两抽头不同且顺序固定 |

**(3) `allzero_err` 粘滞 + W1C——可被软件采样到的告警**
全零死锁告警若做成瞬时组合,状态一离开全零告警即消失,软件采样不到。故做成**粘滞 FF**:`state==0` 置 1 并保持,直到 `err_clr` 清除。优先级**检测 > 清除**——故障仍在(state 还是全零)时即便软件来清也清不掉,只有故障消失后才清得掉,语义正确。真正的 W1C 寄存器位于 `scrambler_top` CSR,核通过 `err_clr` 提供清除通路。

**(4) 复位/`force_rst` 置全 1——天然非零初值**
`rst_n` 和 `force_rst` 都把 state 置 `{N{1'b1}}`,而非全 0。这本身就是个合法非零种子,从源头规避"全零死锁"这个最坏特例;真正的工作种子随后由 CSR 经 `seed_load` 载入(且零种子被 `internal_seed_load` 拦死)。

**(5) 两端输出策略不对称(有意为之)**
- **发送端 `scrambler_core`:组合输出、零延迟**。`dout = din ⊕ state`(经位序翻转),`dout_valid = din_valid && en`。`en` 拉低时 state 冻结、`dout_valid` 拉低,实现背压。发送端从第一拍起输出的就是合法扰码数据,不需要"同步"概念,故不寄存。
- **接收端 `descrambler_core`:寄存输出 + `locked` 门控、+1 拍延迟**。`dout`/`dout_valid` 一起打一拍,并用 `locked` 门控:锁定前 `dout_valid=0`、`dout=0`,锁定后逐拍放出还原数据。这给下游一个"一拍一个、valid 只在同步后为 1"的干净分帧接口——正是纯组合 + 长高 valid 所缺的(组合输出全程活着、无字边界,详见回环验证中发现的分帧问题)。

> 为什么两端不同:接收端存在"未同步→已同步"的过渡,必须靠 `locked` 定帧、挡住垃圾;发送端没有这个过渡。若发送端下游也需要严格分帧,可在其外部再寄存一拍。

**(6) `locked` 计数的 off-by-one 陷阱(v1.3 修正)**
锁定计数器采用"先比较、后自增"结构时,比较值必须写 `LOCK_CYCLES - 1` 而不是 `LOCK_CYCLES`:计数器从 0 起,第 k 个有效拍开始时计数值是 k-1,所以"第 `ceil(N/W)` 拍末拉高"对应的比较值是 `LOCK_CYCLES - 1`。初版误写成 `LOCK_CYCLES`,导致 `locked` 晚一个有效拍拉高,把第一个**本已可正确还原**的字也压掉了——不是同步期垃圾,是真实数据丢失。修正后 `locked` 与状态寄存器真正灌满精确对齐;同时计数器在锁定后冻结(自增以 `!locked` 门控),防止溢出回绕。配套地,输出级更新条件由 `locked` 收紧为 `locked && valid`:锁定后的无效空拍 `dout` 保持清零,不再加载组合垃圾值,波形确定、也省无谓翻转。

**(7) `PARITY_ERR`——影子奇偶寄存器,检测优先于清除(v1.5 新增)**
`allzero_err` 只覆盖"state 变全零"这一种故障;`state` 若被 SEU(单粒子翻转)等物理故障打成任意**非零**值,全零检测形同虚设。做法:维护一个与 `state` **同步更新**的 1-bit 影子寄存器 `state_parity`——`state` 的每一个更新分支(`rst_n`/`force_rst`/`seed_load`/移位)都在同一个 `always_ff`、同一拍里,顺带算出新 `state` 对应的奇偶值写入 `state_parity`。检测逻辑比较"现算的 `^state`"与"存的 `state_parity`":正常工作时二者恒等(同一份逻辑算出来的),一旦不等,说明 `state` 被 RTL 描述之外的路径改动过——两个物理上独立的触发器组不太可能被同一次故障同时篡改到恰好还满足奇偶一致。告警复用 `allzero_err` 的粘滞 FF + "检测 > 清除"优先级结构(见(3)),但配独立的 `parity_clr` 输入 / `parity_err` 输出,不与 `err_clr`/`allzero_err` 共用——STATUS 里两个告警位必须能各自独立清除。

三个实现陷阱都在"移位分支怎么增量更新 `state_parity`"上:
- **不能对整个新 `state` 重新做一次 `^`**——移位分支里新 `state` 是"新移入的 W 位 + 旧 state 里留存的 N-W 位"拼起来的,增量算法是 `(新移入部分的奇偶) ^ (留存部分的奇偶)`,对应 RTL 是 `^scrambler_out ^ (^state[N-W-1:0])`(发送端,移入的是核算出的输出)或 `^din_core ^ (^state[N-W-1:0])`(接收端,移入的是收到的数据,与其纯前馈的性质一致)。
- **非阻塞赋值语义陷阱**:同一分支里若写成先算 `^state` 再用于 `state_parity`,读到的是**本拍更新前**的旧 `state`,而不是"即将写入的新 state"——必须显式用增量公式算出与新 `state` 匹配的奇偶,不能偷懒直接引用 `state` 变量。
- **复位值必须用 `N` 不用 `W`**:`rst_n`/`force_rst` 把 `state` 置 `{N{1'b1}}`(N 位全 1),`state_parity` 也必须算 `^{N{1'b1}}` 的奇偶,而不是 `^{W{1'b1}}`——用错参数在 N、W 都是偶数(默认 N=58、W=8)时数值上恰好都是 0,仿真表面不报错,换一组奇偶性不同的参数就会出错,是同一类"巧合掩盖参数化 bug"的陷阱(参见(2))。

局限性:奇偶校验只保证抓到**奇数个 bit** 同时翻转的故障;偶数个 bit 同时翻转,奇偶结果不变,检测不到——这是奇偶校验固有的能力边界,不是实现缺陷,写文档/寄存器手册时应明确标注。

### 5.10 `scrambler_top`(封装层)实现方案

> 定位:两个 core 只懂数据通路,不懂寄存器、模式和软件语义。`scrambler_top` 把它们封装成一个软件可配置的模块,自身**不含任何扰码数学**——所有位级运算都留在核内,top 只做接线、选择、脉冲整形和状态汇聚。参数 `N/W/TAP_A/TAP_B/BIT_ORDER` 原样透传,且**两个核必须用同一套参数**例化。

> ✅ **RTL 已落地(v1.4)**,并通过全模块通检(无 latch/悬空线/多驱动,四模式端到端自洽)。以下 5.10.1~5.10.8 描述的策略均已在 `scrambler_top.sv` 实现。落地阶段确认/踩过、值得固化的几条陷阱见 **5.10.9**。

#### 5.10.1 职责分解(五大块)

| #   | 块        | 职责                                                      |
| --- | -------- | ------------------------------------------------------- |
| 1   | CSR 寄存器组 | 实现 4.3 的寄存器映射,把软件写事件整形成核能吃的单拍脉冲                         |
| 2   | 种子加载通路   | 拼接种子、非零校验回报、与数据流互斥守门                                    |
| 3   | 测试通路     | 周期计数产生 `force_rst`,同步打给两个核                              |
| 4   | 模式数据 mux | 按 MODE 分发输入 valid、选择输出来源                                |
| 5   | 状态汇聚     | `locked` / `allzero_err` / `state_o` 收拢进 STATUS / STATE |

#### 5.10.2 CSR 实现要点

- **普通 RW 位**(MODE / EN / SEED / TEST):常规寄存器,复位到安全默认(MODE=bypass、EN=0)。
- **W1P(SEED_CTRL.LOAD)**:写 1 这个"事件"本身转成一拍 `seed_load` 脉冲发往发送核;寄存器不存值,读恒 0。
- **W1C(STATUS.ALLZERO_ERR)**:真正的粘滞位在核内——"故障还在就清不掉"的语义由核的优先级(检测 > 清除,见 5.9(3))保证;top 只做通路:软件对该位写 1 时,向核发一拍 `err_clr`,核自己决定清不清。top 不要另存一份影子粘滞位,否则两份状态会漂移。
- **NONZERO_OK(只读)**:核对零种子是**静默拒绝**(没有任何反馈端口),所以这个位必须由 top 自己用"种子寄存器 ≠ 0"组合算出,不能指望核报告。
- **种子拼接**:`{SEED_HI, SEED_LO}` 取低 N bit(N=58 时 SEED_HI 只用低 26 bit,多余高位写忽略、读 0)。

#### 5.10.3 种子加载与数据流互斥(必须守门)

`seed_load` 在核内优先级高于移位。若加载脉冲与有效数据同拍:当拍的字照常用旧状态算出并**发出**(`dout_valid=1`),但这 W 个输出 bit **不会**移进状态寄存器(state 被种子覆盖)→ 发送端"最近 N 个输出"的记录与线上真实数据脱节 → 接收端接下来 `ceil(N/W)` 个字全解成垃圾;更糟的是收端 `locked` 粘滞不掉,**垃圾字会被标成 valid 交给下游**,系统层毫无告警。核有意不管这件事(保持核的简单),约束必须在 top 落地,二选一并写进寄存器手册:

- **方案 A(推荐)**:加载脉冲与"扰码通路当拍有有效数据"互斥——有数据在流时本次加载被拒绝/挂起,可加一个只读 BUSY 位让软件先查再写;
- **方案 B**:允许加载,但当拍强制压掉 `dout_valid`,把受污染的字挡在线外(代价:丢一个字,且对端会观察到一个 valid 空洞)。

#### 5.10.4 测试通路(周期性 force_rst)

`TEST.FORCE_RST_EN` 使能一个自由计数器,数到 `PERIOD` 归零并发一拍 `force_rst`,**同时接两个核**:发端状态置全 1 产生可重复波形,收端同拍重新武装同步(清 `locked` 和计数器),两端节奏保持一致。使能关闭时计数器清零、不发脉冲。正常工作模式下此功能必须关闭。

#### 5.10.5 模式数据 mux(接线表)

| MODE | 发送核输入 | 接收核输入 | dout 来源 | 输出延迟 |
|---|---|---|---|---|
| 0 bypass | 冻结(valid=0) | 冻结(valid=0) | `din` 直通 | 0 拍 |
| 1 scramble | 外部 `din` | 冻结 | 发送核 | 0 拍(组合) |
| 2 descramble | 冻结 | 外部 `din` | 接收核 | +1 拍(寄存) |
| 3 loopback | 外部 `din` | 发送核 `dout`/`dout_valid` 直连 | 接收核 | +1 拍 |

三条接线原则:

1. **不用的核 valid 给 0**:状态冻结,不白翻转(低功耗),也避免无关数据污染状态——切回该模式时状态仍是走时的样子。
2. **loopback 片内直连**:发送核的 `dout`/`dout_valid` 原样接接收核的 `din`/`din_valid`,不出芯片。自测判据:`d̂ == d`(逐 bit)。
3. **en 汇聚**:两核的 `en` = `CTRL.EN` 与外部背压相与;任一拉低,全链冻结,`dout_valid` 同拍拉低。

#### 5.10.6 三个必须写进接口文档的行为

1. **延迟随模式变**:bypass/scramble 零延迟,descramble/loopback +1 拍。下游只能凭 `dout_valid` 对齐,**不得假设固定延迟**。
2. **模式切换需复位**:运行中改 MODE 会残留上一模式的状态(尤其收端 `locked` 粘滞不掉,切换后可能把未同步数据标成 valid)。实现上推荐:top 检测到 MODE 写入值发生变化时自动补一拍 `force_rst`;退而求其次,寄存器手册约定软件流程"清 EN → 发 force_rst → 改 MODE → 置 EN"。
3. **BIT_ORDER 全局一致**:两个核用顶层同一个 `BIT_ORDER` 例化。loopback 是片内直连、中间没有"外部总线",发送核的出门翻转与接收核的进门翻转天然抵消,回环自洽,无需特判。

#### 5.10.7 状态汇聚与回读

- `STATUS.LOCKED` 直连接收核 `locked`(只读);`STATUS.ALLZERO_ERR` 直连发送核粘滞位(W1C 通路见 5.10.2);`STATUS.PARITY_ERR` 是两个核各自 `parity_err` 的 `||` 合并(见 5.9(7)、5.10.9(7)),清除脉冲 `parity_clr` 同时喂给两个核。
- `STATE` 快照:两个核各有一个 N-bit `state_o`,均 > 32 bit 数据口。**落地实现拆成 4 个只读地址**(0x18/0x1C 发端低/高段,0x20/0x24 收端低/高段),各读各的,不用先查模式再解释数据。高段用 `{{32-(N-32){1'b0}}, state[N-1:32]}` 补零(拼接段必须带宽度,`'b0` 这类无宽度字面量在 `{}` 内非法)。

#### 5.10.8 时钟域

本方案假定 CSR 与数据通路**同时钟**,全模块单时钟域。若 CSR 总线在异步时钟域:MODE/EN/种子等准静态配置过两级同步器(或约定"只在 EN=0 时改配置");LOAD/`err_clr` 等单拍脉冲必须走脉冲同步器(toggle + 边沿检测),否则快时钟域会漏采;`N/W/TAP_A/TAP_B/BIT_ORDER` 是 elaboration 常量,不存在 CDC 问题。

#### 5.10.9 RTL 落地陷阱(知识点固化,v1.4)

> 封装层落地时踩过/确认过的关键决策,固化成文,避免重蹈。与 5.9(核内落地要点)配套。

**(1) `bypass` 的 `dout_valid` 必须额外 `&& en`**
`EN`(总闸)对所有模式一视同仁。走核的模式(scramble/descramble/loopback)总闸藏在核 `en` 里自动生效;但 `bypass` 数据**绕开核**、没经过任何 `en` 门控,总闸必须在 top 出口自己补:`dout_valid = din_valid && en`。漏补则模块被关/被背压时数据仍往下游捅。

**(2) `seed_load` 守门用 `&&` 不是 `||`**
守门条件是 `seed_load = seed_load_comb && !(scr_din_valid && en_scrambler)`——"当拍**没有有效数据正在被扰码**才放行"。若误用 `!(A || B)`,按德摩根变成"连模块使能都关掉才放行",而 scramble 模式 `en_scrambler` 基本恒 1,**种子永远载不进去**。守门语义见 5.10.3。

**(3) `force_rst` 双来源用组合 `OR`,不得塞入无关信号**
`force_rst = (test_en && counter==period) || (prev_mode != mode)`——两个独立事件(test 周期截短波形、mode 切换清残留)用 `OR` 并联,不用 if-else 争优先级。**绝不能把 `seed_load`/`err_clr` 塞进 `force_rst`**:核内 `force_rst` 优先级高于 `seed_load`,同拍并发会把要载的种子清成全 1(丢种子);`err_clr` 与状态重置更是毫无关系。一个信号的来源集合必须清晰单一。

**(4) `logic x = 表达式;` 是初始化不是连续赋值**
模块层对 variable(`logic`/`reg`)写 `= expr` 只在 time 0 执行一次(变量初始化),**之后不再更新**。要连续赋值必须 `wire x = expr;` 或 `logic x; assign x = expr;`。此坑不报错、行为诡异、极难查。

**(5) 拼接位宽逐段验算、不用无宽度字面量**
读回 `csr_rdata` 每个 `case` 分支拼接结果必须**正好 32 bit**(逐段相加验算);拼接 `{}` 内每段都要带宽度(`6'b0` 合法,`'b0` 非法)。注意:`csr_rdata = '0;` 这种**赋值**里的 `'0` 合法,一旦进 `{}` 就要带宽度——两个场景规则不同。

**(6) 读口只放软件需要看的状态**
内部脉冲(`seed_load_comb`/`err_clr_comb`)、中间信号不得出现在任何读回位;`NONZERO_OK` 由 top 组合自算(核不反馈);W1P 的 LOAD 位读回恒 0(它是事件不是状态)。

**(7) `parity_err` 双核合并用 `||` 不是 `&&`(v1.5 新增)**
两个核各自独立监测自己的 `state` 并产生 `parity_err`,顶层只留**一个**合并后的 STATUS 位,合并逻辑是 `parity_err = parity_err_scr || parity_err_des`——任一核检测到故障就该让软件看到告警。误用 `&&` 会变成要求两核**同时**故障才报警;两个物理上独立的核几乎不可能被同一次故障在同一拍同时命中,等于把这个告警做成了摆设(数值上"看起来能编译、能跑",但功能上永远不会触发)。清除脉冲 `parity_clr_comb`(监听 STATUS bit2)同时喂给两个核共用,但清不清得掉是每个核**各自独立**判断的(检测优先于清除,逐核判断,见 5.9(7))——不会出现"清了一个核的故障、连带误清了另一个核仍然存在的故障"的情况,因为两个核的粘滞 FF 是各自独立的物理寄存器,只是共享同一个清除脉冲输入。

## 6. 工业级设计考量

| 维度 | 要求 | 落地手段 |
|---|---|---|
| **可参数化** | 一套 RTL 适配不同级数 / 抽头 / 位宽 | `N`、`W`、`TAP_A/B`、`BIT_ORDER` 全参数化 |
| **复位策略** | 单一复位树,异步置位 + 同步释放 | 复位后强制经 CSR 加载非零种子,禁止用未初始化状态运行 |
| **时钟域** | 核内单时钟域,跨域信号做隔离 | 配置/种子等跨域信号过同步器;抽头等结构参数运行中不可变 |
| **Lint 干净** | 无 latch、无组合环 | 组合逻辑全赋值;反馈一律经寄存器打断 |
| **功能安全** | 状态可诊断、活性可监测 | 状态寄存器加影子奇偶校验(SEU 检测)→ `PARITY_ERR`;全零死锁检测 → `ALLZERO_ERR`;`locked` 活性;Loopback 自测 |
| **DFT** | 状态可观测可控制 | `state_o` 引出;扫描链覆盖;`seed_load` 给已知初值便于 ATPG |
| **低功耗** | 无数据时不翻转 | `en` 背压冻结状态;clock-gating 友好 |
| **可移植** | 不依赖厂商原语 | 标准可综合 RTL,工艺无关 |
| **误码倍增意识** | 文档化,与系统层对齐 | 明确标注"1 错放大成多错",指导系统选重传而非纯 FEC |

### 7.1 故障注入方法论:如何验证一个"正常输入永远触发不了"的告警

`PARITY_ERR` 的检测条件(`^state != state_parity`)在 RTL 逻辑自洽的前提下恒为假——两个影子寄存器由同一份逻辑同步驱动,永远不会自然分歧。因此**没有任何合法的 `din`/CSR 激励组合能触发它**,必须用白盒手段直接从 testbench 打入一次"物理故障"(模拟 SEU),再验证检测/告警/清除链路。

- **手段**:`force`/`release`,而非普通过程赋值。`state` 由 `always_ff` 驱动,SystemVerilog 禁止同一变量再被其它进程写入(`always_ff` 单驱动约束),testbench 里一条普通的层级赋值语句会在多数工具上被判为非法多驱动而编译报错。`force` 不算新增驱动源,是被工具认可的临时覆盖机制;`release` 紧接着立刻把控制权还给 `always_ff`,不改变刚被 force 的值,故障因此以"一次性打入"的方式持久留存,后续 RTL 照常运行。
- **一个工具相关的坑**:在部分 VCS 版本上,`force` 一个**跨两层例化层级**(如 `tb → top → core → state`)的**位选择**(`state[5]`)会在 `-inline` 优化阶段挂死进程(既不报错也不结束,需外部超时强杀)。改成"先在 testbench 变量里算好翻转后的**整条**向量,再一次性 `force` 整个信号"即可绕开,不再对 force 的目标做位选择切片。这是工具特定的经验教训,不是通用的 SystemVerilog 语义问题,但值得记录,免得下次重新踩一遍排查成本。
- **验证的三段论**:① 故障注入后告警必须置位;② 故障仍存在时清除脉冲必须被拒绝(检测优先于清除,复用 `ALLZERO_ERR` 已验证过的优先级模式);③ 只有让 RTL 自身的正常路径(此处是继续送数据,触发移位分支重新算出与当前 `state` 一致的 `state_parity`)把故障"吸收掉"之后,清除才能真正生效——这一步不能靠再次强行覆盖 `state_parity` 来"作弊修好",否则验证的就不是真实的故障恢复路径。

## 9. 一页纸总结

1. **是什么**:数据 ⊕ 伪随机序列;接收端寄存器装"收到的数据本身",收满 N bit 自动锁定,**不传种子**。
2. **两个核就差一句话**:发送端移入"自己的输出"(带反馈),接收端移入"收到的输入"(纯前馈)。
3. **并行很省事**:只要最小抽头 > 位宽 W,窗口内无递归,关键路径恒为 2 级异或,高速无需流水。
4. **两条铁律**:种子必须非零(否则死锁);位序必须对齐(否则解出垃圾且难查)。
5. **一个代价**:误码倍增——系统层用重传兜底,而非纯 FEC。
6. **默认 58-bit**,但级数、抽头、位宽全可参数化。
